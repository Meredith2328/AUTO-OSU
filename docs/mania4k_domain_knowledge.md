# osu!mania 4K 领域知识速查

这是开发 AUTO-OSU 4K 生成器时积累的领域知识，写给要做 4K 相关工具（生成器、分析器、难度评估、练习工具）的人，帮助快速上手。

除非另有说明，数字都是在排位 4K 谱面语料上**实测**的：300 组排位谱、1,000+ 张谱面、0.8–9★，由 `scripts/mania4k_fetch.py` 从 osu! 镜像抓取。只有标为"惯例"或"社区"的条目来自游戏行为或社区资料。

实现细节见 [mania4k_engine.md](mania4k_engine.md)；键型分类的完整论证见 v2 PR 中的 `docs/mania4k_patterns.md`。

## 1. .osu 文件里的 4K

| 要点 | 内容 |
| --- | --- |
| 判别 4K | `[General] Mode: 3` 且 `[Difficulty] CircleSize: 4`（mania 的 CS 就是键数） |
| 轨道 | `lane = floor(x × 4 / 512)`，标准写法是 x = 64 / 192 / 320 / 448；y 无意义（写 192 即可） |
| 长条（LN） | 物件 type 含位 128；结束时间写在 extras 第一段：`x,y,start,128,hitsound,end:0:0:0:0:` |
| 红线 | 不继承时间点：`time,beatLength(ms/拍),meter,...,uninherited=1,...` |
| 绿线 | 继承时间点：beatLength 为负，**SV = −100 / beatLength**；也用来开关 kiai |
| 同时刻多个时间点 | 红线必须排在绿线前（写出时按 `(time, not uninherited)` 排序） |
| OD / HP | 判定窗口与掉血。排位谱按星级的中位数见第 4 节 |

### 下落速度与 SV（容易踩的坑）

osu!mania（stable 与 lazer 默认）的**下落速度随 BPM 变化**，基准是谱面中**覆盖时长最长的 beatLength**。所以只要有多条红线，变速段就会忽快忽慢。

人工谱的做法是在每条红线处放一条绿线，令 **SV = 该段 beatLength / 主 beatLength**，把下落速度归一化。实测排位语料里有多个 BPM 的 4K 谱，**82 %（116/142）做了 SV 归一化**。生成器应当默认这样做。kiai 绿线也要带上所在段的 SV，否则会把归一化覆盖掉。

## 2. 定时（timing）惯例

| 事实 | 数据 / 说明 |
| --- | --- |
| **偏移约定** | 排位谱的音符比解码后音频里的起音**早约 24.5 ms**（逐谱估计，IQR 22.5–27.5 ms，mp3 与 ogg 相同；另一种独立测法得 24.4 ms）。生成器写谱时提前 24 ms，玩家按排位谱校准的 offset 才能直接沿用。 |
| 主 BPM 范围 | 92 % 的排位谱主 BPM 在 100–250 之间。节拍追踪给出的 BPM 要按这个范围折叠八度 |
| 双倍 BPM | 强起音在反拍上和正拍上一样多时，谱师会写成双倍 BPM（≤ 250） |
| BPM 取整 | 谱师偏好整数 BPM。只要漂移可以接受，就应当取最简单的值（我们用全曲累计漂移 ≤ 6 ms 作为整数的门槛） |
| 红线位置 | 放在重拍（小节第一拍）上 |
| 网格 | 绝大多数音符在 1/4 与 1/3 系网格上。候选位置用 1/8 ∪ 1/6，即每拍 12 个刻度，足够覆盖 |
| 节奏家族 | 同一拍里不混用直拍（1/4、1/8）和三连（1/3、1/6） |
| 音符与起音 | 约 **86 %** 的排位音符在 ±8 ms 内有明显起音峰；其余 14 % 是延长线、人声或补充节奏。生成器若要求 100 % 落在起音上，比人更严格，可以接受 |

### 定时难点（按难度递增）

1. **恒定 BPM 的电子、流行曲**：用"让全曲起音落在 1/4 网格上"的 BPM / 相位搜索，可以和人工红线一致到 ±5 ms（单 BPM 歌：测试集 93.5 %，从未使用过的留出集 96.7 %）。
2. **有变速的歌**：变速点检测只做到 47 %（测试集）和 20 %（留出集）的歌与人工一致，是主要短板。
3. **速度漂移的现场录音、rubato**：任何恒定网格都对不上。人工谱用的是**节拍图**：几十到上百条红线跟着演奏走，再配合 SV 归一化。判据可以用"节拍追踪器的拍点到网格的中位距离"，正确的恒定网格通常小于 10 ms，漂移时 20 ms 以上。但**这个距离不能单独作为判据**：语料中有 18 首定时正确的歌，追踪器自己就偏 20 ms 以上（人工红线也一样偏）。
4. **节拍追踪本身混乱的音乐**（古典、氛围、部分朋克）：追踪器的拍间隔变异系数在 0.6 以上，没有可靠解法，只能告警。

## 3. 键型分类（社区共识，摘要）

主要依据 Signicial / Reform 段位（每阶四首：**叠 Jack → 技 Tech → 乱 Speed → 耐 Stamina**；入门段有**切 Stream**）、B 站《4k键型科普》和 osu! wiki。

| 类 | 英文 | 判别核心 |
| --- | --- | --- |
| 切 | stream | 无纵连，以双押、三押为骨架：ljs `2111`，djs `2121`，lhs `3111`，dhs `3131`；对拍、对切 |
| 乱 | speed | 无纵连的高速单音：楼梯及其变形、散点；几乎没有多押，等效 BPM 更高 |
| 叠 | jack | 同轨相邻出现：纵连、子弹（minijack）、小 / 中 / 大叠 |
| 技 | tech | 切、叠、乱混在同一段 |
| LN | long note | 长条为主 |

trill 一词两义：

- 作为**基础键型**（交互：单手、双手或散点的交替），它是以上各类的组成单位；
- 作为**段落类型**（交互段、长交互），它和切、技同一尺度，指交互出现频率高且连续很长的段落。

**等效 BPM** = BPM × 分度 ÷ 4。讨论切速、乱速时一律换算到 1/4。

自动判定（每 4 拍窗口）可以只用几个特征：每行音符数、相邻行共享轨道比例（纵连率）、楼梯率、交互率与最长连续交互、LN 行比例、三押行比例。实测：

- 3.5★ 以上的谱里，乱窗口的等效 BPM 中位数为 195，切窗口为 163；
- 交互段只占 0.22 % 的小节。

## 4. 难度与星级

星级用 osu! 官方算法的 Rust 实现 **rosu-pp** 计算，与游戏内一致。下表是排位谱按星级分段的中位数：

| 星级 | notes/s | 多押行 | LN 比例 | 同轨重复间隔（第 1 百分位） | 最近两行间隔（第 1 百分位） | OD / HP |
| --- | --- | --- | --- | --- | --- | --- |
| < 1.8 | 2.9 | 18 % | 21 % | 300 ms | 125 ms | 6.5 / 6.5 |
| 1.8–2.6 | 5.1 | 33 % | 23 % | 166 ms | 75 ms | 7.0 / 7.0 |
| 2.6–3.5 | 7.6–10 | 40 % | 22 % | 131 ms | 58 ms | 7.5 / 7.7 |
| 3.5–4.5 | 12.3 | 39 % | 20 % | 100 ms | 32 ms | 8.0 / 8.0 |
| 4.5–6 | 14–16 | 36 % | 21 % | 83 ms | 25 ms | 8.0 / 8.0 |

经验：

- 校准星级时，二分"放多少音符"的阈值很稳，目标 ±0.08★ 通常十几次以内就能达到。
- 有些歌撑不起高星。人工谱也是如此：同一首歌的排位谱会停在较低星级。**宁可停在较低星级，也不要硬塞音符**；与上一难度相差不到 0.4★ 的难度直接跳过。
- 等效 BPM 的经验范围（社区）：切 160–300，分水岭约 200；叠 100–190。

## 5. 谱面风格与段落结构（实测）

### 整谱风格

先按风格分组，再比较分布。不同风格的分布差别极大，全部混在一起统计会得出谁都不像的"平均谱"。

| 风格 | 张数 | 中位星级 | 构成 |
| --- | --- | --- | --- |
| 切 | 202 | 3.1★ | 切 55 %，乱 20 % |
| 乱 | 138 | 1.7★ | 乱 61 %（低星的单音入门谱居多；3★ 以上 38 张） |
| 叠 | 61 | 4.1★ | 叠 42 %，切 19 %，技 11 % |
| LN | 281 | 3.3★ | LN 73 % |
| 混合 | 167 | 3.4★ | LN 33 %，切 31 %，技 13 % |

- **同一组谱里风格常常不统一**：有多个难度的谱面组中，只有 30 % 所有难度同一风格（不同难度常由不同谱师制作，风格随难度变化）。
- **风格只能部分从音频预测**：用 13 个音频描述量加星级做逻辑回归，分组交叉验证准确率为 42 %，只看星级是 37 %。LN 与切 / 乱能部分区分，叠和混合几乎完全取决于谱师偏好。

### 段落与强度

- 按音乐的自相似新颖度切段落后，人工谱在**段落边界处**的密度变化是段内的 **2.7 倍**（|Δlog nps| 0.38 对 0.14）；键型在边界处改变的概率是 81 %，段内是 64 %。
- **一段一个主键型**：段内主键型平均覆盖 69 % 的小节（LN 谱 81 %）；人工谱一段里最多混用两种键型。
- **密度跟随音乐强度**：小节密度与响度、高频通量的 Spearman 相关约 +0.5，与单纯的起音数量只有 +0.2。
- 按段落能量分级（休息 / 低 / 中 / 高潮），密度从谱面均值的 −45…−60 % 变到 +5 %。高潮处换用更难的子键型，例如切谱里 ljs 换成 djs、hs，叠谱里大叠占比从 29 % 升到 59 %。

### 人工谱的可玩性细节（生成器常见缺陷的对照）

| 指标 | 排位谱 |
| --- | --- |
| 多押行 | 35.6 % |
| 纵连（相邻行共享轨道） | 17.8 % |
| 同手连续（第 95 百分位） / 最长锚点 | 2.0 / 3.3 |
| 左手占比 | 0.50 |
| LN | 21.3 %（各星级都在 20 % 左右） |

## 6. 评估方法与陷阱

- **按谱面组（set）划分训练集和测试集**，不要按单张谱划分：同一组谱共享音频，按谱划分会泄漏。
- **查重复音频**：不同谱面组可能是同一首歌的不同上传。用 0.1 s 帧的 mel 指纹做 30 s 窗口的归一化互相关，已知重复约为 0.97；0.5 s 的粗指纹区分不开。
- **记忆差距检验**：分别在训练歌和测试歌上，比较生成谱与人工谱的一致性。我们的结果是精度 89.6 % 对 89.6 %、召回 64.1 % 对 62.2 %，差距接近 0，说明没有在背谱。
- **另取一个从未碰过的留出集**：开发中看过测试集，阈值就可能被测试集"调"过；新抓一批更早的排位谱（与已有语料零重叠）再测一遍。
- **卡点检验不要循环**：生成器用自己的起音检测选点，再用同一个检测器验证，是自证。换一个独立的检测器（例如 librosa 的 onset strength），对人工谱和生成谱做同样的对齐曲线（音符 ±60 ms 处的平均起音强度），比较两者的峰值高度和位置。
- **从未有人做过谱的音乐**：从 Internet Archive 的 netlabel 合集抓 CC 授权音乐，并在 osu! 镜像上查标题确认没有谱，用来检验泛化。注意这类音乐里原声、现场录音的比例远高于排位语料，定时会明显变难。
- **比较要在同一风格内进行**：用"人工谱是什么风格就按什么风格生成"的方式对比；跨风格对比没有意义。
