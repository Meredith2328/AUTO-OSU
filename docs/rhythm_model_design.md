# 自训节奏模型 v0 设计稿（2026-09-15 定稿）

目标：先把"节奏层"训出来替换规则版的 `rhythm.py`，坐标沿用规则/扩散，约束用规则。
训练在服务器 + wandb，本机只做数据检查和推理。

**已定决策**：1/4 网格；自回归与掩码并行解码两条都训并对比；条件 = 星级/CS/AR/OD/HP/年份 + 拍长 + 局部密度（训练时 20% 丢弃）；
首次训练直接全量 74 分片；音频特征先纯 mel（v1 做显式鼓通道消融）。
代码在 `autoosu/ml/`，已在本机 CPU 上冒烟通过（数据集、两种模式前向/采样、训练脚本含评估出图、端到端生成）。
服务器命令见第 6 节。

## 0. 已测得的数据事实（8 个分片，15,012 张 std 谱面，抽样 600 张）

| 事实 | 数值 | 对设计的影响 |
| --- | --- | --- |
| 物件落在 1/4 网格上的比例 | 98.4%（加 1/12 后 99.8%） | 1/4 网格够 v0 用；9 星以上只有 72%，高星需要 1/12 或自适应网格 |
| tick 类别占比（1/4 网格） | 无 38.6% / 圆圈 14.5% / 滑条头 11.2% / 滑条身 22.0% / 滑条尾 11.1% / 转盘 2.6% | 比预想均衡，不需要重加权，但滑条身占比大，要防模型靠"延长滑条"刷准确率 |
| 每张谱面 tick 数 | 中位 1442，p90 3006 | 上下文 1024-2048 就能覆盖大半首歌 |
| 红线数 | 中位 1，p90 11，最多 371 | 变速歌按红线分段铺网格即可，不能假设单红线 |
| 星级分布 | 10/25/50/75/90 分位 = 2.0 / 2.5 / 3.8 / 5.1 / 6.0 | 条件覆盖 1.5-6.5 星最可靠，8 星以上样本少 |
| 年份 | 2007-2025，近几年占多 | 年份做条件，老图风格可被区分开 |

全量数据集：74 个分片、46,386 首歌、约 13-14 万张 std 谱面、79 GB（压缩音频）。服务器上预处理 32 进程约 30 分钟，特征约 50 GB。

## 1. 数据 pipeline

1. **来源与筛选**：HF `project-riz/osu-beatmaps`，mode=0，approved ∈ {ranked, approved, loved}，星级 0.5-10，≥30 物件，音频 ≤ 10 分钟。
2. **音频特征**：16 kHz 单声道，log-mel 64 维、10 ms 帧，uint8 量化存 npy。备选：80/128 维；或额外加我们规则版的鼓/旋律 onset 通道（4 维）作为显式特征。
3. **标签**：按谱面自己的红线逐段铺 1/4 网格；每个 tick 一个类别（无 / 圆圈 / 滑条头 / 滑条身 / 滑条尾 / 转盘）。折返滑条 v0 当整段；新 combo 和 hitsound v0 不学，用规则。
4. **切分**：按 beatmapset 划分，验证 3%，另留 20 首固定试听歌。
5. **增广**：v0 只随机裁剪。v1 候选：变速 0.9-1.2x（同步缩放红线）、增益、SpecAugment。
6. **推理时的 timing**：训练用人工红线（真值）；推理用我们的 timing 估计器，或接 Mapperatorinator 的 timing 模型。写 .osu 时统一提前 26 ms。

## 2. 每个 tick 的输入与条件

| 输入 | v0 | 备注 |
| --- | --- | --- |
| 音频块 | tick 前后各 80 ms 的 16 帧 × 64 mel，线性投影 | v1：先过一个卷积/Transformer 音频编码器再按 tick 采样，感受野扩到 ±0.5 s |
| 小节内位置 | tick 序号 mod (拍号 × 4) 的 embedding | 让模型知道重拍在哪 |
| 拍长 | **新增**：当前红线的拍长（ms），归一化 | 否则模型不知道 1/4 tick 是 75 ms 还是 150 ms |
| 局部响度 | ±2 s 平均能量，按曲 z-score | 段落强弱 |
| 上一个 tick 的类别 | embedding（teacher forcing） | 自回归 |
| 全局条件 | 星级、CS、AR、OD、HP、年份（连续量 → MLP） | |
| **局部密度**（建议新增） | 训练时用真值：±8 小节内每小节物件数；推理时用户指定；训练时 20% 概率丢弃 | 直接解决"键的量"，比 logit 偏置可控 |
| 谱师 ID（可选） | 7.6k 谱师 embedding，20% 丢弃 | 风格模仿 |
| 标签描述符（可选） | 146 个 tag 多热 | 风格控制，Mapperatorinator 有 |

## 3. 模型

- **范式 v0：因果 Transformer**，逐 tick 采样。理由：离散稀疏事件天然适合、结构约束（滑条头后只能接身/尾）好加、密度可控、最快出结果。
- **备选 v1：掩码式并行解码**（MaskGIT / 离散扩散）：一次生成整段，天然带"整小节节奏型"视角，可局部重生成。数据表示完全相同，可在同一份数据上对比。
- 规模：v0 384 维 × 6 层（约 1100 万参数）验证管线；服务器正式版 768 维 × 12 层（约 9000 万），上下文 2048 tick，flash/sdpa attention。
- 损失：交叉熵 + label smoothing 0.05。可选双头：先"有没有物件"再"是什么类型"，让密度校准更直接。
- 采样：温度、top-p、结构约束掩码、密度条件；按难度可加最小间隔约束（沿用 `difficulty.py` 的规则）。

## 4. 训练与评估（wandb）

- AdamW lr 3e-4、cosine、bf16、batch 64 × 1024 tick、10 万步起。
- 每 1000 步：验证损失、准确率、**onset F1**（有物件的 tick 是否命中，不看类型）、各类 F1、密度校准（预测 vs 真值每小节物件数）、间隔分布散度。
- 每 5000 步：对固定 5 首歌生成一版，渲染节奏图 PNG 上传 wandb，人工看。
- 终验：用 `scripts/compare_maps.py` 与 Mapperatorinator、人类谱面对比，再试听。

## 8. v0 训练记录（2026-09-15，服务器 GPU 4-7，各双卡 DDP）

语料 139,582 张 std 谱面。27.6M 参数，512 维 × 8 层，有效 batch 128，6 万步，约 0.28 秒/步。
前 2 万步生成指标（验证集 6 条序列，给真实局部密度作条件）：

| 步数 | 自回归 onset F1 | 掩码 onset F1 | 密度误差（两者） | 间隔散度 ar / masked |
| --- | --- | --- | --- | --- |
| 2000 | 0.52 | 0.52 | 0.6 / 1.0 | 0.039 / 0.104 |
| 8000 | 0.56 | 0.69 | 0.22 / 0.22 | 0.044 / 0.075 |
| 16000 | 0.74 | 0.79 | 0.17 / 0.16 | 0.013 / 0.011 |
| 20000 | 0.70 | 0.82 | 0.14 / 0.12 | 0.016 / 0.017 |

参照：同一首歌两个人类难度之间的 onset F1 约 0.74（星级相近）。

**发现**：v0 的自回归只能看到当前及过去 tick 的音频（因果注意力盖住了未来的音频块），掩码版是双向的，能"听完整句"。
这是自回归落后的主要嫌疑。**v1 改动**：`audio_ctx_layers` 在标签层之前加双向、不含标签的音频上下文层
（`encode_audio` → `decode`），自回归解码器由此获得未来音频；采样时先对整首歌分块编码一次，再逐 tick 解码。
**试听结论（用户在 osu! 里玩过三版，2026-09-15）**：掩码 v0（密度自选，2.7 物件/秒）手感最好；指定密度 5（4.2/秒）反而不如；
自回归 v0 有严重坏习惯（副歌里 6 秒转盘、12 个转盘），且从 16000 步起平台在 F1 0.70-0.74。
**决定：放弃自回归路线**，只作记录；掩码 v0 从第 24000 步的 last.pt 续训到 6 万步（GPU 6,7），
同时训 masked v1（4 层双向音频上下文 + 6 层解码，35M，GPU 4,5）做等容量对照。
自回归在这个任务上的教训：因果注意力让它听不到后面的音频，而"转盘"类别是它不确定时的逃生口；
若将来重启自回归，需要前瞻音频（v1 结构）和采样期禁止转盘。

## 9. 坐标层 v0（2026-09-15 启动）

**为什么不能直接用 osu-diffusion 的公开权重**：它用 `max_diffusion_step: 100`（满程 1000 步只训最后 100 步）训练，是精修器；
从纯噪声生成时 35.6% 物件出界，精修模式只把我们规则摆放的坐标中位移动 46 像素，布局不变。
另外它的条件里含"到上一个点的距离"（跨度是别人给的），所以它本来就不负责设计跨度。

**方案**：把 osu-diffusion 的代码复制到 `coord/`（MIT），用我们的 13.9 万张谱面从零训练，改动三处：
`max_diffusion_step: 1000`（满程）；新增 `distance_dropout_prob: 0.5`（一半样本把距离条件置零，学会自己定跨度，
另一半保留距离，兼作精修）；条件只保留星级和 CS（去掉谱师/标签/谱面风格类），wandb 项目 `autoosu-coords`。
数据：`scripts/coord_make_ors.py` 把 HF 分片转成它要的 `TrackNNNNN/beatmaps/*.osu + metadata.json` 布局，
星级用 rosu-pp 算 nomod 和 DT 两档（DT 增广用）。配置 `coord/configs/diffusion/coord_v0.yaml`：DiT-B，全局 batch 128，20 万步。
推理：沿用 Mapperatorinator 的 `diffusion_pipeline`，需要加"距离置零"开关并从本地目录加载 `tokenizer.pkl` / `model_ema.pkl`。

**进展（同日）**：训练 6.5 步/秒，第 1 万步从噪声出坐标只有 1% 出界；第 5 万步（25%）的摆放已明显比规则版舒展、接近 Mapperatorinator。
**发现的问题**：模型画的滑条路径远短于节奏要求的长度（它看不到 SV，只看时间偏移），后处理会把 SV 压到 0.2 来迁就；
临时解法是把后处理的锚点拉伸上限放开（`--max-stretch 1000`），按要求长度等比放大锚点、SV 保持 1.0，形状保留、尺度修正。
**v1 要做**：把"要求的滑条像素长度"（或 px/ms 速度）作为每个滑条点的条件特征喂给模型，从根上消除尺度歧义；
同时把跨度也作为可选条件（距离置零 vs 给定），让节奏层/规则层能指定强度。
掩码 v0 最终最佳：第 40000 步 onset F1 0.963、密度误差 0.10。

**坐标 v0 完成（20 万步，约 8.5 小时，最终损失约 0.13）**：最终版摆放 0 出界、相邻距离中位 123 像素、SV 全 1.0（拉伸修正后）。
同一随机种子下 5 万 / 10 万 / 20 万步的布局几乎一致，说明布局判断早已收敛，后半段训练主要在细节。
检查点本地：`runs/coord_v0_ckpt200000/export`。合成流程：`autoosu --rhythm-model` 出节奏 → `scripts/place_with_diffusion.py --diff-ckpt ... --zero-distances --random-init --steps 10 --max-stretch 1000`。

**下一步候选**：
1. 坐标 v1：把要求的滑条像素长度（或 px/ms）作为逐点条件；把"跨度"从置零改为可选给定（强度控制）。
2. 把两步合成合并进 `autoosu` 命令行（`--coord-model`），推理环境统一。
3. 用不同随机种子出多版，让用户挑；加 CFG 尺度试验（`--cfg-scale`）。
4. 节奏层的 1/12 网格与三连音、谱师风格条件。

## 10. 产品化 v0.1（2026-09-16）

用户玩过四首歌的合成谱面后判定"达到基本要求"，转入产品化：中英双语 GUI、exe、开源。同日发现的缺陷：
Run It 有 12 条滑条路径出界（最多 140 像素）——原因是 `--max-stretch 1000` 只按长度放大锚点、不检查边界。

**坐标推理搬进 autoosu**（`autoosu/ml/coord_infer.py`，不再依赖 Mapperatorinator 的 venv）：
按训练数据格式自己构造 token 序列（16 类：圈 / 新 combo 圈 / 转盘头尾 / 滑条头 / 贝塞尔·圆弧·红锚点 / 末锚点 / 5 种重复数的滑条尾），
上下文 = 时间正弦嵌入 + 距离置零嵌入 + 类别 one-hot（272 维）；1024 长窗口、128 重叠、±128 带状注意力；
去噪过程中每步按当前锚点重算滑条尾坐标（与训练一致）；cfg=1 时不再复制批次，算力减半。
模型文件改为 `weights_only=True` 可加载的 fp16 单文件：`models/coord_v0.pt`（261 MB）、`models/rhythm_v0.pt`（57 MB）。

**滑条贴合**（`autoosu/sliderpath.py`）：自己实现 L/P/B/C 路径采样与长度；`fit_slider` 围绕滑条头缩放到要求长度，
出界则依次尝试镜像弯向、绕头旋转（小角度优先），都不行才取最大可容纳尺度并对该滑条加本地绿线降 SV（时长不变）。
整数化后再迭代 4 次修正长度（扁圆弧对取整极敏感）。四首歌重新贴合后路径 0 出界，且全部无需降 SV。
另外快歌按 `min(1, 180/BPM)`（下限 0.75）压低 SliderMultiplier（`effective_preset`），210 BPM 从 1.4 降到 1.2。

**速度**：Run It（3:12）Hard 一个难度，RTX 4090 16 秒，16 核 CPU 69 秒（100 步扩散）。GUI 提供 50/100/200 步三档。

**GUI**（`autoosu/gui.py` + `autoosu/i18n.py`，customtkinter）：拖放/浏览歌曲、四个难度勾选、输出目录、生成后自动
`os.startfile(.osz)` 导入 osu!、高级选项（种子/BPM/偏移/谱师名/星级/质量/设备/引擎/试听 mp3）、模型缺失时一键下载
（`autoosu/models.py`，GitHub Release 资源 + sha256 校验）、设置持久化到 `%APPDATA%\AUTO-OSU\settings.json`。
`AUTO-OSU.spec` + `scripts/build_exe.ps1` 打 onedir exe（CPU torch 版为默认发布包，模型放在 exe 旁 `models/`）。

**仍未解决 / v1**：坐标模型不知道滑条要求长度（形状对、尺度靠贴合）；节奏模型无谱师风格条件；单红线。
