AUTO-OSU architecture

Song in, beatmap out: rules handle analysis and timing, two trained models do the mapping, the result is packed as an .osz and handed to osu!.
Input

Any audio or video file

mp3 · ogg · wav · flac · m4a · aac · wma · opus · mp4 · mkv · webm …

→

Input normalisationaudio_io.py

libsndfile decoder, ffmpeg fallback (bundled) — video files contribute their audio track

→

Analysis waveform

22.05 kHz mono float32

+

Audio for osu!

mp3 / ogg-vorbis copied through, everything else transcoded to 192 kbps mp3

↓
Analysis (rules)

Audio analysisaudio.py

Harmonic / percussive split (HPSS) · onset envelopes per drum band (kick / snare / hat) · loudness · onset list with strength and sustain

→

Timingtiming.py · rhythm.py

Tempogram BPM with octave correction · 1 ms offset refinement on the waveform · downbeat phase · loudness sections → kiai

↓
Mapping (models)

Rhythm modelrhythm_v0.pt

Masked tick transformer, 29 M parameters · 1/4-beat grid, each tick → none / circle / slider head / body / end / spinner · conditioned on star rating, CS, AR, OD, HP, loudness, beat length

→

Coordinate modelcoord_v0.pt

Diffusion transformer (DiT-B), 130 M parameters, trained from scratch · object tokens (time + type) → x / y from pure noise · conditioned on star rating and CS, picks its own spacing

→

Slider fittingsliderpath.py

Scale the learned shape about the head to the required length · mirror / rotate if it leaves the field · shorten with a local green line only as a last resort · every path stays inside 512 × 384

↓
Output

Beatmap writerbeatmap.py · package.py

.osu v14 · objects 26 ms early (ranked-map convention) · kiai and SV green lines · metadata · zipped into an .osz

→

.osz

all chosen difficulties in one package

→

osu!

opened automatically, imports itself
